How to share PdDroidParty patches

Zipping patches to "pdz"

You can share your PdDroidParty compatible patches with people by zipping up the folder with your patch in it and renaming the file extension from .zip to .pdz.

The name of the top level directory will be used as the name of the patch, when the name hasn't been specified to PdDroidParty by other ways (see later). For example MyPatch.pdz will contain a folder called MyPatch/, which contains your files like droidparty_main.pd etc.

You can also include in droidparty_main.pd a Pd comment with the text "version: 99" to set the version of your patch so that people receiving them will know what version they are being asked to install. Each time you release a new version of your .pdz file you can increment the version number.

Sharing the "pdz"

You can share the pdz in different ways.

  • When you send a pdz file to somebody, PdDroidParty will launch and run the patch on their device if they have the app installed.

If you make the pdz file available for download on a server, there are several ways to provide the URL to PdDroidParty so it can download it.

  • Locally: by editing the links in PdDroidParty (menu -> Edit links), you can enter the URLs of remote pdz files. You can even enter in the links the URL of a remote "links" text file, where several patches URLs and further links redirections are listed.
  • Publically: if you provide us the URLs of your patches, or even better, the URL of your "links" file, we can register it in the "users" list, so that anybody can download your patches easily.
    To do this, open an issue in the PdDroidParty github, or write to the Pd list, or to our personal addresses.

How the "links" file works

Each link line must contain 3 tokens: TYPE NAME URL
Tokens can be enclosed in double quotes if they contain spaces (mostly for NAME)

TYPE can be: pdz for patch, links for text file containing links, gh for github API.
Exemples:

pdz "my super piano" https://my_site/my_patches/piano.pdz
will install piano.pdz as "my super piano"

links "my synths collection" https://my_site/my_patches/synths.txt
will parse the links in synths.txt under new dir "my synths collection/"

gh user_patches https://api.github.com/repos/USER/REPO/releases/tags/TAG
will add pdz assets of the TAG release into new dir "user_patches/"; if release notes contains links, add them too.

gh user_patches2 https://api.github.com/repos/USER/REPO/contents/export_dir
will add pdz files contained in the "/export_dir/" of the repo and its subdirs into new dir "user_patches2/"; also, parse any file called "links.txt" in "export_dir/" or any subdir.

For more details about how the "links" work, see the LINKS HOWTO
